- 2026-11-18 — P2, first evaluation (1,500 deck pairs, sides swapped, vs the rules-based player): 0.7%. Two bugs, both fixed test-first: (1) the cast model splits its confidence across identical cards (three Plains at 0.3–0.5 each), so a per-card threshold skipped land drops — scores are now pooled per card; (2) plans were keyed on id(game), and Python reuses ids, so from the second game in each worker the player followed a dead game's plan and passed every turn — plans now reset per game. Fixed: **23.5% ± 0.8%** (control rules vs rules 48.6%). Diagnosis: it plays lands like the rules-based player (7.3 vs 7.7 a game) but casts 6.4 spells against 10.5 and attacks 5.6 times against 8.7. People hold instants and tricks for the opponent's turn; this player never acts at instant speed, so held cards rot. Options: casting what's left in the second main phase 31.7%, attacking at a 0.35 threshold 26.9%, both **39.4% ± 0.9%**. Tuned against the same opponent, so read that as an upper bound. P2's goal (beat the rules-based player) isn't met: turn-level imitation copies people's restraint without their instant-speed follow-through. That gap is P3's job.
- 2026-11-18 — P3 designed (docs/play/P3_DESIGN.md): one network scores every legal move (state tokens for every visible object, action tokens that point at the objects they name, policy and value heads); distillation from the smart player first, then PPO self-play against a league (itself, past checkpoints, the rules-based and smart players) with a decaying KL leash, reward only for winning. Measured: ~208 decisions with a real choice per game (priority 165, attackers 25, targets 7, blockers 6); rules-based self-play ~290 games/s in one Python process; an observation ~14 µs.
- 2026-11-18 — P3a done. Bindings: the observation now carries `combat` (attackers, blocker→attacker pairs) and `legal_cards` (the card behind each object a move names, so a library search still says which card); 1 new binding test. `bolt.play_encoding` (encode: a token per visible object (own hand, both battlefields with tapped/power/toughness/damage/counters/sick/attacking/blocking, graveyards, exile, stack; the opponent's hand is a count), a game vector, and per legal move its kind, pointers to the objects it names, those cards, its numbers and the player it targets; collate pads a batch) and `bolt.play_net.PlayNet` (transformer over the game and object tokens; move tokens scored against the game token; value head in [-1, 1]); 5 tests written first: only visible cards, every pointer lands on the named object, attackers marked in combat, object order doesn't matter, a batch gives a proper distribution over each position's legal moves. - 2026-11-18 — P3b done. Bindings: `Game.smart(rollouts, candidates, seed)` returns the smart player's move one decision at a time; test: with the engine's seeds it replays the engine's own smart games exactly. `bolt.play_runner`: `run_games` keeps a batch of games in lockstep with seats "net", "rules" or "smart", sends every waiting network decision through one forward pass, plays single-option moves without asking, and records steps (encoding, move, log probability, value; or the smart player's moves as teacher labels); an engine error ends one game, not the batch. `run_parallel` splits jobs over spawn worker processes and reruns a dead worker's share in a fresh pool. 6 tests written first (games finish with legal moves and full records, greedy play reproducible, rules and smart seats replay the engine's games exactly, teacher labels, parallel = serial). Laptop, 6 workers, 0.9M-parameter network: net vs net 41 games/s (5,900 decisions/s), net vs rules 95 games/s, smart 1 × 2 self-play recording both sides 14 games/s = 2,300 teacher decisions/s (160 a game), so a few million distillation examples take under an hour.
