# Engine plan: phase 3

A Magic rules engine in Rust, built so decks can be **played** instead of **judged**. This file is the
working plan for autonomous build sessions. Each session starts here, then reads `LOG.md`, and leaves
both up to date when it stops.

## Why

Every win rate so far is a judge's prediction. The judges learned from human-built decks, so they can
share blind spots. Played games settle it. Played games are also the training ground for a gameplay
agent later.

## What the card audit says

`docs/engine/CARD_AUDIT.md` (generated by `scripts/card_audit.py`):

- **281 non-basic cards**, sorted into tiers by rules complexity: 8 vanilla or keyword-only, 59 one-shot
  effects, 169 with ongoing rules, 45 complex.
- **Partial coverage isn't enough for real decks.** Even implementing cards from most-played down, 50%
  of real 17lands decks only become fully playable at 219 cards, 80% at 243, and 95% at 263. Limited
  decks are diverse.
- **So the plan is:** (a) aim for the whole set, and (b) make the engine useful early through
  **restricted drafts**. The simulator can draft from packs filtered to supported cards (a "cube" of
  what's implemented), so real games, bots and RL can run long before card 281.

## Architecture

```text
engine/                    Cargo workspace
  bolt-core/               rules: state, zones, turn structure, priority, stack, combat, SBAs
  bolt-cards/              card definitions: data-driven where possible, code where not
  bolt-py/                 PyO3 bindings: Game, legal_actions(), step(action), observation()
```

- **Game state is plain data.** `Game { players, zones, stack, turn, step, priority }`, cloneable, so
  agents can search and tests can compare states.
- **Actions are an enum,** and the engine is the only thing that changes state.
  `legal_actions(&Game) -> Vec<Action>` and `apply(&mut Game, Action) -> Result<Events, RulesError>`.
  Illegal actions are errors, never silent no-ops.
- **Effects are a small DSL** (`Effect::Damage { amount, target }`, `Effect::Draw`, `Effect::Pump`,
  `Effect::CreateToken`, ...) so most cards are data. Cards that don't fit get a hand-written
  `impl CardBehavior`.
- **Deterministic RNG** seeded per game, so any failing game replays exactly.
- **Unsupported cards are listed, never skipped.** `bolt_cards::supported()` is the source of truth for
  restricted drafts.

## Milestones

Each milestone ends with tests passing, CI green, a commit, and a `LOG.md` entry.

| # | Milestone | Done when |
|---|---|---|
| M0 | Workspace and CI | `cargo fmt --check`, `cargo clippy -D warnings` and `cargo test` run in GitHub Actions next to the Python job |
| M1 | Rules core with creatures | Two players, 40-card decks, mulligans, turn structure, mana from lands, casting creatures, combat with every evergreen keyword, damage, SBAs, win/loss. 10,000 random-agent games, no panics, every game ends |
| M2 | The stack and one-shot effects | Instants with priority passing; targets and the effect DSL; enters and dies triggers; tier 1–2 cards (67) each with a rules test from its text |
| M3 | Ongoing rules | Triggered and activated abilities, auras, equipment, P/T-modifying static effects (layer 7), modal spells. Tier 3 cards in build order, tracked against the coverage curve |
| M4 | Complex cards | Tier 4, one at a time, each with tests |
| M5 | Python bindings and a baseline player | `bolt_engine.Game` in Python; a rules-based player (attack when safe, block to survive, curve out); games/second benchmarked |
| M6 | Validation | Play the RL bot's decks against the human model's decks, thousands of games per pairing. Compare played win rates with judge B's predictions |
| M7 | A stronger pilot | A search pilot (rollouts with the baseline, no peeking at hidden cards) beats the baseline clearly; M6 rerun with it on both sides |

## Testing rules

- **Every card gets a test** written from its rules text: a minimal board, the card's effect, then the
  expected state.
- **Every rule the core implements gets a test** citing the Comprehensive Rules section it follows
  (e.g. `// CR 510.1c: blocked creature assigns combat damage`).
- **Fuzzing:** random legal actions across many seeded games. Invariants are checked after every
  action: no negative counts, cards in exactly one zone, life totals consistent with damage events.
- **The engine never panics on a legal action.** A panic is a bug with a reproducible seed.

## Session protocol (autonomous work)

1. Work on the `engine` branch. Pull, read this file and `LOG.md`.
2. Pick the next unchecked item in the current milestone.
3. Write tests first, then code. Run `cargo test` and `cargo clippy` before every commit.
4. Commit small, push, and append one line to `LOG.md`: what changed, tests added, what's next.
5. **Judgment calls:** choose the conservative option, write it in `QUESTIONS.md` with the reasoning,
   and keep going.
6. **Stop and write it up instead of retrying** if: a test failure can't be explained after two
   attempts, anything hangs, or the next step needs a decision only Adam can make.
7. Heavy compute (RL, long fuzzing) runs on the **CPU**, one job at a time. Never on the Apple GPU.
8. **Every test, fuzz or long run goes through `scripts/guard.sh`** with a time limit and a 2 GB
   memory cap, e.g. `scripts/guard.sh 300 2000 -- cargo test`. Nothing runs unattended in the
   background. On 2026-11-05 an engine loop that never ended grew two fuzz runs to ~42 GB each
   and restarted the laptop. The engine also stops any single action past `WORK_BUDGET` (a
   million zone changes) with a panic naming the seed. After a hang, rerun only that seed until
   it's fixed.
